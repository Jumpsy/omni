# Frontend Architecture
1. Inspect the stack first.
2. Preserve conventions.
3. Avoid unnecessary dependencies.
4. Prefer semantic HTML.
5. Separate server and client concerns.
6. Keep components small.
7. Avoid premature abstraction.
8. Validate external data at boundaries.
9. Handle loading, empty, error, success.
10. Document non-obvious decisions.
11. Keep secrets out of the repo.
12. Avoid monolith components.
13. Align architecture with existing routing.
14. Write meaningful tests.
15. Inspect rendered output after implementation.
